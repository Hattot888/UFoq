# معرض أفق للفنون المعاصرة (HORIZON Contemporary Art Gallery)
### منصة تجارة إلكترونية متكاملة للوحات الفنية مع نظام تحليلات سلوكية حقيقي

منصة متكاملة واحترافية لبيع واقتناء اللوحات الفنية الأصلية، مبنية بتقنيات الويب القياسية (HTML5 / CSS3 / Vanilla ES Modules) مع قاعدة بيانات PostgreSQL ومصادقة سحابية عبر Supabase، ونظام قياس وتحليلات سلوكية طرف أول حقيقي ومقاس (First-Party Behavioral Telemetry Engine) للمالك دون أي أرقام وهمية أو افتراضية.

### 1. وصف المشروع
معرض رقمي متكامل للأعمال التشكيلية والمعاصرة يُتيح:
- تصفح كتالوج اللوحات الفنية بتصميم يلائم صالات العرض الفنية المعاصرة (Art Gallery Aesthetic).
- البحث الفوري والتصنيف حسب الفئات والترتيب حسب الأسعار أو الأكثر تفاعلاً ومشاهدة بناءً على تحليلات حقيقية.
- صفحة مستقلة ومفصلة لكل لوحة برقم مرجعي مستقر (`product.html?id=UUID`).
- سلة مقتنيات تفاعلية محفوظة في المتصفح مع إعادة احتساب الأسعار الموثوقة لمنع التلاعب.
- رحلة شراء تجريبية توضيحية موثقة (Demonstration Checkout Flow).
- نظام حسابات مستخدمين كامل عبر Supabase Auth.
- لوحة تحكم إدارية خاصة بالمالك محمية بالتحقق المزدوج تعرض بيانات حقيقية مسجلة من نشاط الزوار (مؤشرات الزيارات، الزوار المميزون، مشاهدات الأعمال، إضافات السلة، قمع التحويل، ورسم بياني تفاعلي).

### 2. حزمة التقنيات
- **الواجهة الأمامية**: HTML5 Semantic + CSS3 Vanilla (Mobile-First Responsive، خط القاهرة Cairo من Google Fonts، تصميم عربي RTL أصيل).
- **منطق البرمجة**: JavaScript (ES Modules المعيارية - بدون أي أطر عمل ضخمة وبدون React/Vue).
- **قاعدة البيانات والتخزين**: Supabase PostgreSQL + Row Level Security (RLS).
- **المصادقة**: Supabase Auth (Email & Password).
- **المكتبات الخارجية**: `@supabase/supabase-js@2` مستورد عبر CDN قياسي (ESM).

### 4. فتح المشروع في VS Code
1. شغّل برنامج Visual Studio Code.
2. اضغط على `File -> Open Folder...` (أو `Ctrl + K, Ctrl + O`).
3. اختر مجلد المشروع `e:\mohsen`.

### 5. التشغيل المحلي عبر Live Server
نظراً لأن المشروع يستخدم وحدات جافا سكريبت الحديثة (`type="module"`)، يجب تشغيله عبر خادم HTTP محلي لتفادي قيود CORS الخاصة بملفات `file://`:
1. في متجر إضافات VS Code، ثبّت إضافة **Live Server** (من تأليف Ritwick Dey).
2. انقر بالزر الأيمن للماوس على ملف `index.html`.
3. اختر **Open with Live Server**.
4. سيفتح المتصفح تلقائياً على العنوان: `http://127.0.0.1:5500/index.html`.

> **ملاحظة هامة:** في حال لم يكن Supabase مرتبطاً بعد، سيعمل المتجر فوراً في وضع **المعاينة التجريبية** بالكتالوج المدمج، وستظهر شارة تنبيهية علوية لطيفة ترشدك لكيفية الربط.

### 6. إنشاء مشروع Supabase
1. توجه إلى [https://supabase.com](https://supabase.com) وسجل دخولك (أو أنشئ حساباً مجانياً).
2. اضغط على **New project**.
3. حدد اسماً للمشروع (مثلاً: `horizon-art-gallery`).
4. اختر كلمة مرور قوية لقاعدة البيانات واحفظها في مكان آمن.
5. حدد أقرب منطقة جغرافية (مثل Frankfurt أو London) ثم اضغط **Create new project**.

### 7. تنفيذ مخطط قاعدة البيانات schema.sql
1. في لوحة تحكم Supabase، اضغط على تبويب **SQL Editor** من الشريط الجانبي الأيسر.
2. اضغط على **New query**.
3. افتح ملف `supabase/schema.sql` من المشروع وانسخ محتواه بالكامل.
4. الصق الكود داخل محرر SQL في Supabase واضغط على زر **Run** (أو `Ctrl + Enter`).
5. ستظهر لك رسالة نجاح `Success. No rows returned`.
6. تم إنشاء جداول: `products`, `analytics_events`, `admin_users`, `demo_orders` وتفعيل Row Level Security وتطبيق كافة السياسات والفهارس تلقائياً.

### 8. إدراج عينات اللوحات seed.sql
1. في محرر SQL Editor بـ Supabase، افتح استعلاماً جديداً **New query**.
2. انسخ كامل محتوى الملف `supabase/seed.sql`.
3. الصقه في المحرر واضغط **Run**.
4. سيتم إدراج 8 لوحات فنية معاصرة ببياناتها وأسعارها ومقاساتها الواقعية.
*(تنبيه: seed.sql يحتوي فقط على كتالوج اللوحات ولا يخترق أو يولد أي أحداث تحليلات وهمية للحفاظ على مصداقية الأرقام).*

### 9. ضبط بيانات الاتصال في js/config.js
1. في لوحة Supabase، اذهب إلى: **Project Settings** (أيقونة الترس أسفل اليسار) -> **API**.
2. ستجد حقلين رئيسيين:
   - **Project URL**: يشبه `https://abcdefghijkl.supabase.co`.
   - **Project API Keys**: انسخ المفتاح الموسوم بـ `anon` `public` (يبدأ بـ `eyJ...`).
3. افتح ملف `js/config.js` في VS Code وضع القيم:
```javascript
export const CONFIG = {
  // ...
  SUPABASE_URL: 'https://your-project-id.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...',
  // ...
};
```
4. احفظ الملف (`Ctrl + S`).

> **تحذير أمني قطعي:** لا تضع أبداً مفتاح `service_role` أو كلمة مرور قاعدة البيانات في أي ملف فرونت إند! مفتاح `anon` هو الوحيد المخصص للمتصفح ومحمي بسياسات RLS.

### 10. إعداد نظام المصادقة Supabase Auth
1. في لوحة Supabase، اذهب إلى تبويب **Authentication** -> **Providers**.
2. تأكد من تفعيل مزود **Email**.
3. (اختياري للتطوير السريع): في تبويب **Authentication** -> **URL Configuration** أو **Email Templates**، يمكنك تعطيل خيار `Confirm email` إذا أردت تسجيل الدخول فوراً دون انتظار رسالة تفعيل البريد.

### 11. تفويض حساب المدير الأول
لحماية لوحة الإدارة من التلاعب، لا يمكن لأي مستخدم عادي أن يصبح مديراً تلقائياً. المالك يقوم بالخطوات التالية لمرة واحدة:
1. افتح صفحة التسجيل في المتجر: `http://127.0.0.1:5500/signup.html`.
2. أنشئ حساباً ببريدك الإلكتروني وكلمة مرورك الشخصية.
3. توجه إلى لوحة Supabase -> **Authentication** -> **Users**.
4. ستجد حسابك المسجل؛ انسخ المعرف الفريد الخاص بك المسمى **User UID** (عبارة عن نص بصيغة UUID مثل `c2b4d9a1-8765-4321-abcd-123456789abc`).
5. اذهب إلى **SQL Editor** في Supabase ونفذ الأمر التالي:
```sql
INSERT INTO public.admin_users (user_id, role)
VALUES ('ضع_معرف_المستخدم_المنسوخ_هنا', 'admin')
ON CONFLICT (user_id) DO NOTHING;
```
6. الآن توجه إلى `admin.html` في متصفحك وسجّل الدخول؛ ستفتح لوحة التحكم فوراً بكامل صلاحيات الإدارة والتحليلات!

### 12. سياسات الحماية RLS
تم تطبيق نظام الحماية على مستوى الصفوف في PostgreSQL:
- **جدول products**:
  - القراءة متاحة للجميع فقط حيث `is_active = true`.
  - الإضافة، التعديل، والحذف مقتصرة تماماً على من يوجد معرفه في `admin_users`.
- **جدول analytics_events**:
  - الإدراج متاح للزوار (المجهولين والمصادقين) فقط لأنواع الأحداث الستة المصرح بها، ويُمنع تزوير معرف مستخدم آخر.
  - القراءة والاستعلام مقتصرة بالكامل على المديرين المصرح لهم فقط.
  - التعديل والحذف ممنوعان من جهة العميل للحفاظ على نزاهة سجلات القياس التاريخية.
- **جدول admin_users**:
  - لا يمكن للمستخدم العادي إدراج نفسه نهائياً؛ الإدراج فقط عبر محرر SQL السحابي أو بصلاحيات الخادم المرتفعة.

### 13. آلية تتبع الأحداث السلوكية
تعتمد المنصة على وحدة `js/analytics.js` التي تطبق سياسة تتبع معيارية وصارمة:
- **الأحداث المصرح بها فقط**:
  1. `site_visit`: يُسجل مرة واحدة فقط لكل جلسة تصفح (`sessionStorage`) عند الدخول للمتجر العام.
  2. `page_view`: يُسجل عند تحميل كل صفحة مستقلة.
  3. `product_view`: يُسجل عند فتح صفحة تفاصيل اللوحة الفنية بمطابقة المعرف الحقيقي `product_id`.
  4. `add_to_cart`: يُسجل حصراً بعد نجاح إضافة العمل للسلة فعلياً.
  5. `sign_up`: يُسجل بعد نجاح إنشاء الحساب عبر Supabase Auth.
  6. `login`: يُسجل بعد نجاح تسجيل الدخول التفاعلي.
- **استثناء الإدارة**: حركة التصفح الداخلي لمدير المتجر في `admin.html` مستثناة تلقائياً من إحصائيات الزوار العامين.
- **معرف الزائر (Visitor ID)**: معرف طرف أول عشوائي (RFC4122 v4 UUID) يُحفظ في `localStorage` دون أي بصمة جهاز تطفلية أو جمع عناوين IP.
- **معرف الجلسة (Session ID)**: معرف مؤقت في `sessionStorage` ينتهي بإغلاق التبويب.
- **تنفيذ غير معطل**: إرسال الأحداث يتم في الخلفية (`async`) دون إيقاف أو تعطيل تفاعل العميل مع واجهة الشراء.

### 14. طريقة حساب مؤشرات الأداء KPIs
تُحسب جميع الأرقام من واقع السجلات المحفوظة في `analytics_events`:
- **زيارات الموقع (Site Visits)**: إجمالي سجلات `event_type = 'site_visit'`.
- **الزوار المميزون (Distinct Visitors)**: عدد معرفات `visitor_id` الفريدة (Set).
- **مشاهدات اللوحات**: إجمالي سجلات `product_view`.
- **إضافات السلة**: إجمالي سجلات `add_to_cart`.
- **مقتنون أضافوا للسلة**: عدد معرفات الزوار الفريدة التي نفذت حدث `add_to_cart`.
- **معدل التحويل (Conversion Rate)**: `(إضافات اللوحة للسلة ÷ مشاهدات صفحة اللوحة) × 100`؛ وتظهر علامة "بيانات غير كافية" عند عدم وجود مشاهدات منعاً للقسمة على صفر.
- **قمع التحويل (Funnel)**: يحسب التسلسل: (الزيارة 100%) -> (نسبة من استعرضوا اللوحات) -> (نسبة من أضافوا للسلة) -> (نسبة من سجلوا أو دخلوا بحساب).

### 15. التحقق من تسجيل الأحداث في قاعدة البيانات
للتحقق بنفسك من أن البيانات حقيقية وتُسجل لحظياً:
1. افتح صفحة المعرض `index.html` في متصفح خفي (Incognito).
2. افتح وحدة التحكم `F12` -> `Console`؛ ستشاهد رسائل المطور:
   `[Analytics 📊] Event: site_visit`
   `[Analytics 📊] Event: page_view`
3. انقر على أي لوحة فنية لفتح تفاصيلها؛ سيظهر الحدث:
   `[Analytics 📊] Event: product_view`
4. اضغط على زر "إضافة إلى سلة المقتنيات"؛ سيظهر:
   `[Analytics 📊] Event: add_to_cart`
5. افتح لوحة Supabase -> **Table Editor** -> جدول `analytics_events`؛ ستجد الصفوف المسجلة بتوقيت UTC ومعرف الزائر ومعرف العمل الفني.
6. افتح لوحة `admin.html` واضغط "تحديث ⟳"؛ ستنعكس الأرقام والمخططات والجدول فوراً!

### 16. التجهيز للاستضافة الساكنة
المشروع مبني ليكون Static Site خالصاً، ولا يتطلب خادماً أو Node.js:
- جميع الروابط واستيرادات الملفات نسبية (`./js/...`).
- الاتصال بقاعدة البيانات ومحرك المصادقة يتم مباشرة من المتصفح عبر Supabase REST APIs.

### 17. النشر على Cloudflare Pages
عند رغبتك في إطلاق الموقع على نطاق عام مجاناً:
1. ارفع المشروع إلى مستودع GitHub (أو استخدم رفع المجلد عبر Cloudflare Dashboard).
2. ادخل إلى لوحة تحكم [Cloudflare Dashboard](https://dash.cloudflare.com).
3. اختر **Workers & Pages** -> **Create application** -> **Pages**.
4. اربط حساب GitHub واختر مستودع `horizon-art-gallery`.
5. في إعدادات البناء (Build settings):
   - **Framework preset**: `None`.
   - **Build command**: اتركه فارغاً.
   - **Build output directory**: `.` (أو جذر المشروع).
6. اضغط **Save and Deploy**.
7. سيعمل الموقع على رابط سريع ومدعوم بشبكة توزيع عالمية مجانية مع شهادة SSL تلقائية.

### 18. القيود الفنية الحالية
- **طبيعة المعرف**: معرف الزائر المخزن في المتصفح هو تقريب إحصائي؛ إذا مسح الزائر ملفات تعريف الارتباط أو استخدم متصفحاً آخر، فسيُولد معرف جديد.
- **أدوات حجب الإعلانات**: بعض إضافات المتصفح الصارمة (Ad-blockers) قد تحجب استدعاءات القياس أو الاتصال بالنطاقات السحابية.
- **التخزين المؤقت للصور**: تعتمد النسخة الحالية على روابط صور مباشرة (Image URLs) بدلاً من معالج رفع ملفات ثقيل لتجنب التكلفة.

### 19. الاعتبارات الأمنية والخصوصية
- لا يتم تسجيل أو إرسال أي كلمات مرور، بطاقات دفع، أو أرقام هواتف داخل جدول التحليلات.
- تلتزم الواجهة بخيار المتصفح `Do-Not-Track` عند تفعيله من قبل المستخدم.
- سياسات RLS تحمي بيانات العملاء وسجلات التحليلات من أي وصول غير مصرح به.

### 20. متطلبات الإطلاق التجاري الفعلي
قبل إطلاق المتجر للبيع التجاري الفعلي واستلام أموال حقيقية، يلزم الآتي:
1. التعاقد مع بوابة دفع إلكتروني معتمدة (مثل Paymob أو Fawry أو Stripe) واستبدال شاشة `checkout.html` التوضيحية بتكامل رسمي مشفر.
2. إضافة سياسة شروط وأحكام وسياسة استرجاع قانونية موثقة وفق اللوائح التجارية المحلية.
3. تفعيل نطاق مخصص (Custom Domain مثل `horizon-gallery.com`) مع شهادة أمان SSL.
4. تفعيل سياسات حدود الطلبات (Rate Limiting) في Supabase عبر Edge Functions لحماية المتجر من محاولات الإغراق.
